# P0/P1 正确性修复设计

日期：2026-08-23

## 背景

当前工作区的功能测试和构建能够运行，但代码审查发现四类上线前必须处理的问题：运行镜像没有包含 Alembic 配置；订单按购物车行重复计算固定金额促销；消费者价格库存问答依赖可关闭的 Agent 工具记录；多 SKU 商品使用最低价 SKU 的促销结果代表所有规格。

本设计只处理这些 P0/P1 问题，以及为使 CI 恢复通过所必需的两处 Ruff 修正。密码令牌撤销、后端全面分层、前端错误状态和样式整改不在本次范围内。

## 目标

- Docker/Render 运行镜像能够找到 Alembic 配置，并在应用启动前完成迁移。
- 一个促销在其业务作用域内每个订单最多应用一次。
- 全场优惠和商品优惠不叠加，自动选择对用户更有利的方案。
- 消费者价格库存问答不受 Agent FunctionTool 初始化状态或启用状态影响。
- 每个 SKU 展示自己的真实价格、可售库存和优惠，不再共享最低价 SKU 的促销结果。
- 保持现有数据库结构、公开请求模型、工具名称和参数兼容。

## 非目标

- 不新增促销叠加、优惠券、会员价或复杂活动规则。
- 不为订单增加促销明细或快照字段。
- 不修改密码失效策略。
- 不全面重构 API、service、repository 分层。
- 不修改前端交互或视觉样式。

## 方案选择

采用聚焦式服务重构：保留现有接口和数据库结构，将订单促销计算和商品价格库存查询收敛到明确的服务入口，并通过现有调用方复用。

未采用最小补丁，因为继续在 `TradeService` 和路由中堆叠查询及计算会扩大职责混乱。未采用全面分层重构，因为它超出本次范围，也会增加与当前大量未提交改动的冲突风险。

## 架构与组件

### 运行镜像

`Dockerfile` 在运行阶段复制根目录 `alembic.ini`。启动顺序保持不变：数据库迁移失败时立即停止，不运行 AI 初始化、演示数据和 Web 服务。

### 促销服务

保留现有 `best_promotion(session, product_id, amount)` 单商品接口，避免影响推荐等现有调用方。新增订单级入口，输入订单商品行的 `product_id` 与金额，输出最终优惠总额和所选方案的应用结果。

订单级计算规则：

1. 对全部行求和，得到订单商品总额。
2. 按 `product_id` 聚合行金额，同一商品的不同 SKU 合并计算。
3. 查询当前有效且与订单相关的全场促销和商品促销。
4. 全场方案只选择一个最佳全场促销，并按订单商品总额计算一次。
5. 商品方案对每个商品选择一个最佳商品专属促销，再将各商品优惠相加。
6. 全场方案和商品方案不叠加，选择优惠金额更高的方案。
7. 两种方案金额相同时选择全场方案，确保结果稳定且容易解释。
8. 单项优惠不超过其作用域金额，最终优惠不超过订单商品总额。

同类候选促销沿用现有确定性顺序：先比较实际优惠金额；金额相同则保留查询顺序中优先级更高、ID 更新的活动。

### 订单服务

`TradeService.create_order()` 继续负责地址校验、购物车校验、SKU 加锁、库存校验、订单和订单项写入。它不再逐购物车行调用 `best_promotion()`，而是在完成有效行整理后把商品 ID 和行小计一次性交给订单级促销入口。

订单仍只保存最终 `discount_amount`，`payable_amount` 继续按商品总额减优惠计算并限制为非负数。本次不增加数据表或迁移。

### 商品价格库存查询服务

新增独立查询入口，输入商品 ID，输出商品及其启用 SKU 的真实数据：SKU ID、名称、价格、可售库存，以及以购买一件为金额基准计算出的 SKU 对应优惠。

每个 SKU 单独计算促销，因此不同价格跨越门槛时不会共用错误结果。零库存但仍启用的 SKU 可以返回，其可售库存为零；只有不存在、已下架或没有启用 SKU 时分别走相应结果。

消费者 `PRICE_STOCK` 问答直接调用该查询入口，不经过 `ToolCenter.execute_by_name()`。Agent 的 `get_product_price_stock` 工具也调用同一入口，但工具注册和启用状态仍只控制 Agent 自主工具调用。

## 数据流

### 创建订单

1. 获取并锁定用户已选购物车行及 SKU。
2. 校验商品状态、SKU 状态和可售库存，形成已验证订单行。
3. 计算订单商品总额，并按商品聚合小计。
4. 促销服务计算全场方案和商品方案，返回二者中更优惠的结果。
5. 使用最终优惠创建订单，锁定库存，写入订单项并删除已结算购物车行。
6. 任何异常都由现有事务边界处理，不提交部分订单、库存或购物车变更。

### 价格库存问答

1. 路由验证 `product_id` 存在。
2. 查询服务验证商品存在且处于在售状态。
3. 查询启用 SKU 并计算每个 SKU 的可售库存和单件优惠。
4. 问答层逐 SKU 生成价格、库存和优惠文本。
5. 无启用 SKU 时返回成功结果和“当前没有可售规格”，而不是工具执行失败。

## 错误处理

- 商品不存在或已下架：返回明确的领域错误“商品不存在或已下架”。
- 商品存在但没有启用 SKU：返回空列表，由问答层生成正常提示。
- SKU 零库存：返回 SKU 和零库存，不把它误判为查询失败。
- 没有有效促销：优惠金额为零，SKU 不包含优惠描述。
- 促销金额超过作用域金额：截断到作用域金额。
- 数据库或迁移异常：保持失败即停止；不吞掉异常或继续启动应用。

## 兼容性

- 保留 `best_promotion()` 的名称、参数和行为，现有推荐逻辑无需同步改造。
- `PRICE_STOCK` 的公开请求和响应模型保持不变，只调整答案文本的促销展示粒度。
- Agent 工具名称 `get_product_price_stock` 及其参数保持不变。
- 不修改数据库结构、历史订单或前端 API 调用。
- 只修复当前 Ruff 报告的行长和导入顺序，不扩展到其他规范整改。

## 测试策略

所有行为修改采用红—绿—重构流程：先添加能稳定复现问题的失败测试，确认失败原因正确，再写最小实现使其通过。

### 部署配置

- 添加配置测试，验证运行镜像明确复制 `alembic.ini`。
- 在环境支持 Docker 时实际构建镜像，并验证迁移入口能够读取配置。

### 促销结算

- 全场固定优惠在多购物车行订单中只应用一次。
- 同一商品多个 SKU 的金额先聚合，再应用一次商品优惠。
- 不同商品可以分别使用各自最佳商品专属优惠。
- 全场方案比商品方案优惠更大时选择全场方案。
- 商品方案总和更大时选择商品方案。
- 两种方案金额相同时选择全场方案。
- 优惠金额不超过其作用域金额或订单商品总额。
- 无有效活动时返回零优惠。

### 商品价格库存

- 未初始化 FunctionTool 时，消费者价格库存问答仍成功。
- FunctionTool 被禁用时，消费者价格库存问答仍成功。
- 不同价格 SKU 返回各自正确的促销结果。
- 下架商品返回领域错误。
- 没有启用 SKU 时返回空列表和正常提示。
- 零库存 SKU 返回可售库存零。

### 完整验证

- 后端完整测试集。
- Ruff 检查。
- Mypy 检查。
- 前端类型检查和生产构建，确认后端改动没有破坏集成。
- Alembic 从空数据库升级到最新版本。
- 检查 Git 差异，确认只包含本设计范围内的改动，且没有覆盖用户原有工作。

## 完成标准

- 所有新增回归测试均经过可观察的先失败、后通过过程。
- Docker 运行镜像包含 Alembic 配置，迁移链可执行。
- 多行购物车不会重复应用同一全场或商品固定优惠。
- 全场与商品优惠遵循二选一取最大值规则。
- PRICE_STOCK 不依赖 FunctionTool 状态，并逐 SKU 返回正确数据。
- 后端测试、Ruff、Mypy、前端类型检查、前端构建和迁移验证全部通过。
