# 商品对比中心设计

日期：2026-08-24

## 背景

商城已经具备自然语言搜索、商品详情、收藏、购物车、订单与 AI 导购，但用户从多个候选商品中做最终选择时，仍需要反复打开详情页并自行记忆价格、库存和参数。现有 AI 导购采用多轮 Agent 与工具调用，适合开放式选购，不适合承担必须立即展示的结构化对比。

本设计新增商品对比中心：基础对比始终快速、公开且可分享；AI 只作为登录用户主动触发的辅助分析，不阻塞商品事实展示。

## 目标

- 用户可从商品列表和商品详情将商品加入对比。
- 对比清单最多包含四件商品，并且只能包含同一分类商品。
- 对比清单无需登录，保存在当前浏览器，并可通过带商品 ID 的链接分享。
- 对比页一次读取全部实时商品事实，按价格、库存、评分、销量、品牌、商品参数和 SKU 规格对齐展示。
- 支持“仅看差异”，降低大表格的阅读负担。
- 登录用户可填写可选购买需求，主动请求一次快速 AI 对比分析。
- AI 不可用、超时或未配置时，基础对比保持完整可用。
- GitHub Pages 展示版可以体验基础对比，不依赖后端或登录。

## 非目标

- 不将对比清单同步到用户账号或跨设备保存。
- 不允许跨分类对比。
- 不让 AI 自动运行，也不在页面加载时占用模型资源。
- 不让 AI 生成或覆盖商品价格、库存、评分等商城事实。
- 不在对比页完成 SKU 选择和直接加购；用户从对比页进入商品详情后购买。
- 不新增商品参数管理体系或强制所有分类使用同一参数模板。
- 不保存 AI 对比历史，不新增数据库表或迁移。

## 方案选择

采用“公开批量事实接口 + 前端本地清单 + 登录后专用单次 AI 接口”。

未直接复用 AI 导购，因为导购包含多轮模型和工具交互，响应时间与输出结构不适合对比表。未开放匿名 AI 接口，因为公开模型能力需要更复杂的匿名限流和防滥用基础设施。未把基础对比设为登录功能，因为商品比较属于浏览决策，公开访问也能让 GitHub Pages 展示版完整呈现核心能力。

## 前端架构

### 对比清单 Store

新增独立 Pinia store，职责仅包括：

- 保存已选商品的最小摘要：商品 ID、分类 ID、名称和主图。
- 加入商品时执行去重、最多四件和同分类校验。
- 移除单件或清空全部商品。
- 将清单写入带版本号的 `localStorage` 键。
- 从分享链接恢复合法商品 ID，并在批量接口返回后用真实数据纠正本地摘要。

store 不缓存完整商品详情，不直接调用 AI，也不负责渲染提示。加入失败返回明确结果码，由页面决定如何提示用户。

### 商品入口

`ProductCard` 增加显式“加入对比/已加入”操作，点击操作不能触发商品详情导航。商品详情页在收藏和购买操作附近提供同样入口。

加入第一件商品后，全局商城布局底部显示对比栏。对比栏展示最多四个缩略项，提供逐项移除、清空和“开始对比”。达到两件商品后才允许进入对比页。尝试加入其他分类时提示“只能对比同一分类商品”，并提供清空当前对比的操作，但不自动丢弃用户已有选择。

### 对比页

新增公开路由 `/compare?ids=1,2,3`。链接中的 ID 是打开分享链接时的输入来源；批量接口验证成功后，规范化后的 ID 同步回地址栏和本地 store。

页面包含：

1. 商品摘要区：主图、名称、品牌、价格区间、评分、评价数、销量和查看详情。
2. 规格对比表：取所有商品 `parameters` 键名的并集，并补充启用 SKU 的属性摘要和总可售库存。
3. “仅看差异”开关：值完全相同的行在开启时隐藏；缺失值显示“未提供”。
4. AI 分析区：可选需求输入框、“AI 帮我选”按钮、加载状态、结构化结论和重试入口。

桌面端固定左侧参数名并按商品分列。移动端保留参数名列，商品列横向滚动，不把四件商品压缩到不可读宽度。

## 公开批量对比接口

新增 `GET /api/v1/catalog/products/compare?ids=1,2,3`，并确保静态路由注册在动态商品详情路由之前。

请求规则：

- `ids` 使用逗号分隔整数。
- 去重后只接受 2–4 个 ID。
- 所有可用商品必须属于同一分类。
- 只返回在售商品及其启用 SKU。

响应包含 `items`、`unavailable_ids`、分类名称和品牌名称。单个商品不存在或已下架时不让整个请求失败，而是放入 `unavailable_ids`；剩余商品不足两件时仍返回事实，由前端展示补选提示。跨分类请求返回明确的 422 领域错误。

repository 使用一次商品批量查询，并通过预加载读取分类、品牌、图片和 SKU，避免逐商品接口请求和 N+1 查询。响应 DTO 只包含对比需要的数据，不返回冗长详情 Markdown 或无关后台字段。

GitHub Pages 展示模式下，前端 API 层从现有 `demoProductDetails` 按相同规则生成同形响应，不发起网络请求。

## AI 对比接口

新增登录接口 `POST /api/v1/ai/product-comparison`。

请求：

```json
{
  "product_ids": [2, 3],
  "preference": "主要用于办公室，重视舒适度，预算 1000 元"
}
```

`product_ids` 去重后必须为 2–4 件，`preference` 可省略并限制长度。服务端不信任前端商品事实，而是重新读取在售商品、启用 SKU、实时价格和可售库存，并再次验证同分类。

模型输入只包含规范化后的必要事实：商品名称、品牌、参数、SKU 属性、实时价格区间、可售库存摘要、评分、销量和用户需求。它不包含冗长 Markdown、图片或历史对话。

接口使用默认启用的语言模型进行一次非思考模式请求，低温度、受限输出长度和 20 秒硬超时，不进入 Agent 工具循环。模型返回结构化 JSON，服务端通过 Pydantic 校验：

- `recommended_product_id`
- `summary`
- 每件商品的 `strengths`、`weaknesses` 和 `suitable_for`
- `considerations`

服务端校验推荐商品和逐项分析 ID 必须属于本次候选。响应结构不提供价格和库存字段，避免前端误用模型生成数值。模型输出非法时返回可重试错误，不用硬凑的模板结论冒充 AI 结果。

## 数据流

### 加入对比

1. 商品卡片或详情页向 compare store 提交商品最小摘要。
2. store 校验去重、同分类和数量上限。
3. 成功后更新响应式状态和 `localStorage`，全局对比栏立即更新。
4. 失败时返回原因，入口页面显示对应提示，现有清单不变。

### 打开对比页

1. 解析并清理地址栏中的重复、非整数和超量 ID。
2. 有 2–4 个 ID 时调用一次公开批量接口；少于两件时直接展示补选引导。
3. 收到事实后移除 `unavailable_ids`，更新 store 和规范化地址栏。
4. 基于商品参数键并集生成对比行；默认展示全部行，用户可切换仅看差异。
5. 同一 ID 组合的成功批量结果在内存中短时复用；重新进入页面时仍会在缓存过期后刷新实时事实。

### 请求 AI 分析

1. 未登录用户点击按钮时跳转登录页，并携带当前完整对比 URL 作为返回地址。
2. 登录用户提交商品 ID 和可选需求。
3. 后端重新查询并校验事实，压缩为模型上下文，执行一次模型请求。
4. 前端只在当前商品 ID 组合和需求仍一致时接收结果，旧请求不能覆盖新选择。
5. 相同 ID 组合与规范化需求的成功结果写入 `sessionStorage`，当前浏览器会话中重复访问可立即恢复。

## 性能设计

- 基础对比只发起一次目录请求，不等待 AI。
- 批量接口只接受最多四件商品，限制查询和响应上界。
- repository 批量加载关联数据，禁止按商品循环查询详情。
- 响应不包含详情 Markdown 和非对比字段，减少传输体积。
- 对比行使用 `computed` 从最多四件商品派生，不用 watcher 复制派生状态。
- 快速变更 URL 或清单时取消旧请求，或使用递增序号忽略过期响应。
- AI 关闭深度思考，只做一次结构化生成，并限制 prompt 和回答长度。
- AI 请求超过 20 秒立即恢复按钮为可重试状态；超时不清空基础表格。

性能验收目标：正常本地演示数据下，批量目录接口服务端耗时低于 500ms；基础对比首屏不依赖模型返回。外部模型网络时间无法绝对保证，但其等待不会影响页面查看和操作。

## 错误与边界处理

- 重复 ID：静默去重并规范化 URL。
- 非法或超过四件的 ID：忽略非法值，只保留前四个合法值并提示链接已修正。
- 少于两件：不调用批量接口，展示继续选择商品的入口。
- 跨分类：store 在正常交互中阻止；服务端对手工构造 URL 再次返回 422。
- 商品下架或不存在：从清单和 URL 移除，列出已失效商品 ID；剩余内容继续显示。
- 无参数：基础事实仍展示，参数区域提示商家暂未提供详细参数。
- AI 未配置、超时、限流或结构校验失败：保留用户需求和基础表格，展示简短错误与重试按钮。
- GitHub Pages 展示模式：基础对比使用本地数据；AI 区明确提示完整部署后可用，不跳转到无效登录流程。
- `localStorage` 或 `sessionStorage` 数据损坏：清除对应版本键并回退为空清单，不影响应用启动。

## 安全与可信度

- 公开批量接口只读取公开在售商品，不暴露成本价、锁定明细或后台字段。
- AI 接口使用现有登录鉴权，并通过请求长度、候选数量、单次模型调用和硬超时限制资源上界。
- 商品 ID、数量、分类、状态和事实全部由服务端重新校验。
- 用户需求按纯文本处理，限制长度，不拼接为可执行工具参数。
- AI 结果只作为选择建议，实时价格和库存始终来自目录接口。

## 测试策略

所有行为变更遵循红—绿—重构：先添加能因缺失行为稳定失败的测试，确认失败原因，再写最小实现。

### 后端

- 批量接口正确去重并返回 2–4 件同分类商品。
- 批量接口一次加载所需商品关系，不出现按商品循环查询。
- 不存在或下架商品进入 `unavailable_ids`，其他商品继续返回。
- 跨分类、非法数量和非法 ID 返回明确错误。
- AI 接口拒绝未登录、跨分类、下架商品和过长需求。
- AI 服务只发起一次模型请求，并传入压缩后的服务端事实。
- 非思考模式、输出长度和 20 秒超时参数生效。
- 合法结构化响应通过；候选外商品 ID、非法 JSON 和超时返回可重试错误。
- AI 响应模型不包含价格和库存字段。

### 前端

- compare store 覆盖去重、同分类、四件上限、移除、清空和损坏存储恢复。
- 商品卡片操作不会误触详情导航，详情页和卡片状态保持一致。
- 对比栏在一件商品后出现，两件后启用开始对比。
- 分享链接恢复、非法链接清理、失效商品移除和 URL 规范化正确。
- 基础表格生成参数并集，缺失值正确显示，仅看差异隐藏相同行。
- 快速切换对比组合时，旧请求不能覆盖新结果。
- 未登录点击 AI 返回登录并保留对比 URL；展示模式不发起 AI 请求。
- AI 成功、缓存恢复、超时、失败和重试状态均不影响基础表格。
- 桌面和移动布局通过组件测试与必要的浏览器交互验证。

### 完整验证

- 后端 Ruff、Mypy 和完整 Pytest。
- 前端完整 Vitest、类型检查和生产构建。
- GitHub Pages 展示构建，验证本地演示对比可用。
- 浏览器手工验证商品列表、详情、对比栏、分享链接、移动横向滚动和登录返回。
- 检查 Git 差异，只提交本功能文件，不包含工作区原有未跟踪内容。

## 完成标准

- 用户无需登录即可从列表或详情选择 2–4 件同分类商品并打开对比页。
- 分享链接可在新浏览器恢复同一组有效商品。
- 基础对比通过一次批量读取展示实时事实，并支持仅看差异。
- 正常本地数据下批量接口服务端耗时低于 500ms，基础页面不等待 AI。
- 登录用户可主动获得一次结构化 AI 对比；未登录、AI 失败或超时均不破坏基础功能。
- 展示版基础对比、完整部署 AI 对比及所有新增测试均通过。
- README 记录商品对比入口、限制、分享方式和 AI 使用条件。
