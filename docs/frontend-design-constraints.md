# 前端设计约束

本项目的前端设计必须同时参考以下两个上游项目，不允许脱离约束自行套用通用 AI 页面模板：

- Taste Skill: https://github.com/Leonxlnx/taste-skill
- Impeccable: https://github.com/pbakaus/impeccable

## 适用边界

### 用户商城

商城首页、商品列表、商品详情、AI 导购入口等偏消费体验的页面，主要采用 Taste Skill 的页面构图、视觉节奏和反模板规则。

### 管理后台与产品界面

管理后台、表格、表单、设置、Agent 执行时间线、Markdown 报告和多步骤交互主要采用 Impeccable 的产品 UI、信息架构、状态设计、可访问性和审计规则。

Taste Skill 明确说明默认规则不面向 dashboard、data table 和 multi-step product UI，因此不得强行把营销页构图移植到管理后台。

## 技术边界

- 保持 Vue 3、Vite、Element Plus、Vue Router 和 Axios。
- Element Plus 只提供交互基础，不直接使用默认主题作为最终视觉。
- 项目必须维护自己的设计令牌，不混用多个设计系统。
- 图标统一使用一个 Vue 图标家族，不手绘 SVG，不用 emoji 代替功能图标。
- 引入任何前端依赖前必须先检查 `package.json`。

## 开工前必须产出

在实现页面前先建立根目录 `DESIGN.md`，至少固定：

- 产品用户与页面类型。
- 视觉方向和明确的反例。
- 主色、强调色、语义色和中性色阶。
- 字体、字号、行高与数字字体规则。
- 间距、圆角、边框、阴影和层级。
- 按钮、输入框、卡片、表格、导航和弹层规则。
- 桌面、平板和移动端断点。
- 动效强度、持续时间、缓动和 reduced-motion 降级。

设计令牌固定后，组件不得临时引入新的颜色、圆角或阴影。

## 硬性反模板规则

- 禁止默认使用紫蓝 AI 渐变、霓虹光晕、全屏玻璃拟态和发光粒子。
- 禁止页面由大量相同白色圆角卡片堆叠组成。
- 卡片只在层级确实需要容器时使用，普通分组优先使用留白、分隔线和版式层级。
- 同一页面只使用一个主要强调色，并保持圆角体系一致。
- 不允许每个标题都配同样的图标方块、小标签或状态圆点。
- 状态圆点只能表达真实在线、库存、运行或告警状态。
- 页面可见文案不使用中文或英文破折号作为装饰性分隔。
- 不使用占位式营销文案、虚假统计数字和无意义图表。

## 完整交互状态

所有数据页面和交互组件都必须覆盖：

- 加载状态：骨架必须匹配最终布局。
- 空状态：解释原因并提供下一步操作。
- 错误状态：在错误发生位置附近给出可执行反馈。
- 禁用状态：说明不可操作原因。
- 成功反馈：用于新增、保存、支付、评价等明确动作。
- 网络重试和重复提交保护。

表单标签必须位于输入框上方，错误信息位于输入框下方，不使用 placeholder 代替标签。

## 响应式与可访问性

- 每个多栏区域必须在组件内显式声明小于 768px 时的布局。
- 桌面导航保持单行；空间不足时收敛菜单，而不是换成两行。
- 文本、按钮、输入框和状态颜色满足 WCAG AA 对比度。
- 所有可点击元素支持键盘操作和清晰的 focus-visible 状态。
- 图片提供有意义的 alt；纯装饰图片使用空 alt。
- 动效支持 `prefers-reduced-motion`，核心操作不能依赖动画才能完成。

## 页面级使用规则

### 商城首页

- 首屏价值表达必须在初始视口内完成。
- 桌面端标题不超过两行，主操作无需滚动即可看到。
- 优先真实商品图，不用 CSS 绘制的假商品图或假界面截图。
- 相邻区块不能连续重复同一种三列卡片或左右图文布局。

### 商品列表与详情

- 筛选项、排序、库存和价格的视觉优先级高于装饰。
- 商品卡片必须展示真实字段，不生成虚构促销或评分。
- 商品详情主图、价格、库存、规格、数量和加购操作应在桌面首屏形成清晰购买区。

### 管理后台

- 信息密度由任务决定，不把所有指标包装成卡片。
- 表格操作保持稳定位置，批量操作与行操作有清晰边界。
- 危险操作需要确认并明确影响范围。
- 数据筛选、分页、加载、空结果和权限不足状态必须完整。

### Agent 执行时间线

- Run 概览和 Step 明细分层呈现。
- Step 必须展示编号、类型、状态、工具名、耗时和可展开的入参/结果。
- 颜色只表达语义，不允许仅靠颜色区分成功、失败和运行中。
- 不展示或暗示模型私有思维链，只展示允许保存的决策摘要。

## 验收流程

每一批页面只进行两轮有界视觉验证：

1. 同时检查桌面和移动端截图，集中记录布局、层级、对比度、溢出和状态缺失问题。
2. 一次性修复后再确认一轮，然后停止无目标的反复润色。

任何页面未覆盖加载、空、错误、移动端和键盘焦点状态，不视为完成。
